# 当前生产状态

**当前实现尚不能用于生产发布。** 安装动作会写文件和注册表，请只在一次性虚拟机里验证。

## 已验证

- 构建器与运行时是两个独立程序，安装包不含构建器。
- ZIP 与 7z payload 按文件头来识别，再选对应的运行时。
- 两个运行时都能正确解开真实归档，结果与预期 SHA-256 一致。
- 卸载程序使用自己的运行时和页面列表，不链接任何解包后端。
- CLI 与 Windows 10+ GUI 驱动同一套构建 API，GUI 依赖不会进入运行时。
- 安装包里带着 payload、项目资源，以及一个自包含的卸载程序，卸载程序有自己的图标和版本信息。
- 安装会解压 payload，把文件和卸载程序放进新目录，写入 manifest 与卸载项；
  卸载只删 manifest 里记录的内容。
- 目标目录里已经有同一个项目时，就地升级：删掉新版 payload 里不再包含的文件，
  任何一步出错都会恢复到升级前的版本。
- 首屏用原生方式渲染背景位图和 Unicode 文字，窗口没有边框、四角是圆的，可以拖动、最小化和关闭，
  鼠标移到可点击控件上会显示手型光标。
- 每个生成的文件都过了一遍 PE 导入审计，检查 Windows 7 SP1 x64 兼容性。
- 进度页实时汇报状态，完成页可以启动已经部署好的应用。
- 快捷方式和自启动项在安装时创建、卸载时还原，回滚路径也一样处理。
- 卸载会结束正在运行的产品、清掉快捷方式；只有用户取消勾选保留数据时，才会删掉声明过的用户数据。
- 内嵌的 Rhai 引擎负责执行 `scripts/install.rhai` 与 `scripts/uninstall.rhai`，
  脚本里用的原语直接复用内置的部署、回滚和 manifest 代码。脚本失败会回滚，
  脚本漏掉 manifest 清理时，库会补上。
- 流式布局覆盖嵌套 `VBox`、`HBox`、`Content`，支持内边距、外边距、百分比尺寸、
  `justify-content` 与 `align-items`。
- 文案里的 Markdown 链接点一下就打开配置好的网址，`close_confirm` 弹出的确认框带着项目自己的皮肤，
  目录选择框会把选中的路径写回布局里的 TextInput。
- 脚本发出的提示、报错和提问（`show_message`、`show_error`、`ask_yes_no`）也画在向导窗口里，和产品
  自己的对话框一个样子；用户在卡片上点中的那个按钮，就是脚本接着往下走的答案。没有东西可画的运行
  仍旧用系统对话框。
- 控件按布局声明的 `background`、`border-color` 与 `border-radius` 来绘制；语言菜单展开后上下键、
  回车与 Esc 都能用。
- 文本框可以直接编辑：点一下落下闪烁光标，输入就插入，Backspace 与 Delete 删除字符，方向键、Home、
  End 移动光标；按住左键拖动或双击可以选中文字并高亮，Ctrl+A 全选，Ctrl+C/X/V 复制、剪切和粘贴，
  Ctrl+Z/Y 撤销与重做，Ctrl+Backspace/Delete 和 Ctrl+左右键按词操作，连续输入合并成一步。
  声明 `readonly` 的字段保持只读展示。
- `TextInput` 可以把工程对取值的规矩写在版面上：`required`，按字符数算的 `min-length` 与
  `max-length`，以及 `pattern`——一种掩码，`*` 是任意长的一段（可以为空），`?` 恰好一个字符，
  整段值都要对得上。没写规矩的字段一律合格，可留空的字段空着也算合格。`enabled-when` 用 `valid`
  或 `invalid` 点名这样的字段，写多个条件时用逗号隔开、全部成立才算成立。
  `value-source="field-error:<字段 id>"` 的 `Label` 画出页面为「值最先破坏的那条规矩」写下的文案，
  文案按工程自己的语言查表，值合格时什么都不画。空字段照样收得下光标，页面因此可以先要一个目录，
  等用户填了才让安装开始。
- `Select` 是页面提供的一种选择，不只是语言控件：它按 `<Option>` 子元素列出选项、显示当前选项的
  文字，并记下用户点中那一行的 `value`。`RadioButton` 用 `group` 归属一组、用 `value` 代表组内的
  一个取值，`checked="true"` 标出这一组起始选中的行，点任意一行就为整组换掉这个值。
  `enabled-when="<id>:<取值>"` 能读其中任何一个，id 是选择框自己的或单选组的名字；菜单展开后
  和语言列表一样吃上下键、回车与 Esc。
- 流式布局拿 `flex-basis` 当起点来分配剩余空间；每个元素都可以设 `align-self`；
  嵌套容器按里面的内容参与外层测量；
  绝对定位的元素可以用 `right`/`bottom` 或 `inset` 简写从另一侧定位。
- 工程可以把脚本要跑的辅助程序一起打包：`resources.tools_dir` 指到的目录按原样进安装包，子目录
  也在内，脚本用 `get_tools_dir()` 把它摊到磁盘上并拿到路径。没打包工具的工程，以及向一个没带工具的
  安装包要工具的脚本，拿到的是空字符串和一条日志告警，安装照常继续。
- 项目脚本可以写入当前用户的环境变量（`set_env`、`remove_env`），也可以登记文件类型
  （`register_file_association`、`unregister_file_association`）。两者都经过 manifest：
  安装记下写过的值和建过的键，卸载只按记录收回这些——`Environment` 记的是值而不是键，
  所以 PATH 不会跟着被删掉。
- 容器声明 `flex-wrap` 后，一行放不下就会折行；默认仍然是先压缩可收缩项。
- 声明 `scrollable="true"` 并给出 `id` 的流式容器保住自己拿到的尺寸，子元素按各自声明的尺寸排开，
  放不下的部分整体裁掉：被滚过去的那一行既不画出来也不再登记点击，列表下方的按钮因此能接到它本来会
  吃掉的点击。滚轮按每格 48 像素移动它，贴尾部那条滚动条显示列表露出了哪一块，点滑块两侧的轨道各翻
  一页。
- 安装包会写入应用程序清单：打开 `install.require_admin` 后，Windows 会在进程启动前弹出提权确认；
  `ui.dpi_aware` 告诉系统窗口要不要自己缩放。两个都不配置时，就按普通程序的方式运行。
- 构建器会把每个语言文件与默认语言、页面实际引用的键比一遍，报出缺文案的语言，
  以及 `supported_locales` 里列了却没有对应文件的语言。
- 卸载完成后，临时目录里的清理副本会立刻删掉卸载程序和已经清空的安装目录。
  目录里还有用户自己的文件时就保留目录，清理副本做完也会自动退出并消失。
- 项目声明 `advanced.silent_mode_support` 后，加上 `--silent` 就会静默安装；
  声明 `advanced.uninstall_mode_support` 后，同样可以静默卸载。静默运行不开任何界面，
  只接受 `--dir`，其它参数一律拒绝，结果靠退出码和标准错误返回。项目没有声明时，安装包会直接拒绝，
  不会悄悄装上或卸掉。
- 工程可以把安装内容切成组件：`resources.payload_file` 是每次都装的基础载荷，`components.items` 里的
  每个组件带自己的 ZIP 或 7z 归档，页面上同名的 `Checkbox` 决定这次装不装它，脚本用
  `is_component_selected` 与 `selected_components` 问同一个答案。写了 `required` 的组件一律装，
  页面上没有这个复选框（含静默运行）就按 `default` 决定。所有归档由同一个运行时解压，格式不一致
  会在构建时被拒绝；两个归档带同一个相对路径会在安装时报错，而不是按声明顺序互相覆盖。
- 工程可以声明机器上必须先有的东西。`dependencies.items` 里每条写清怎么认（查文件，
  或查注册表的某个值是否存在、是否等于某个值、是否不低于某个版本）、怎么装（随安装包带一个 `.exe`，
  或按 URL 下载一个），以及缺了算不算致命。安装在解压 payload 之前先问一遍：已经有的不动，缺的装上，
  必需的装不上就停下来并报出依赖名与安装程序的退出码，非必需的只记一条告警。
  下载回来的程序先对得上工程记下的 SHA-256 才允许跑，对不上就地删掉。装进机器的是依赖本身，
  它不在卸载清单里——产品卸掉之后，机器上原本缺的东西仍然留着。脚本要自己决定时机时，
  `dependency_installed`、`install_dependency`、`download_file`、`download_file_with_hash` 与
  `sha256_of_file` 问的是同一份声明、走的是同一条取文件的路径。
- `crates/nano-installer-core/tests/e2e_setup.rs` 里的安装包级用例会自己造项目、
  构建安装包并真的装上：文件逐字节写盘，manifest 与卸载项写入，升级时删掉旧文件、
  保留不属于它的文件，卸载时清掉产品、注册项和目录；机器缺的依赖真的被装上，
  下载来的依赖先过一遍哈希校验才跑。39 个用例里有 13 个会开出向导窗口并驱动它：
  一个量它画出来的客户区，一个走一遍工程声明的翻页动作，一个在取消按钮上停掉正在跑的任务，
  一个往页面要的输入框里敲进一个目录、再由它把安装开起来，一个点中单选按钮里安装键等待的那一行，
  一个在列表上滚一格滚轮、点中滚进来的那一行，一个点中脚本自己亮出的卡片、读脚本每次作答之后
  写回的内容，一个把页面上填的字与选中的那一行读进脚本，一个在窗口里勾上一个组件、清掉已经勾着的
  另一个、看装出来的是哪些，一个把指针挪到按钮上、按住不放，再把按钮声明的三张状态图从窗口里读
  回来，一个读窗口在按钮、输入框和页面空白处分别回哪种标准光标，一个用上下键、Enter 和 Escape 走
  一遍语言菜单，还有一个点开选目录按钮、再关掉外壳的选目录对话框。开窗口要可交互的桌面会话，
  没有桌面的机器上这 13 条跳过，
  `NANO_INSTALLER_E2E_REQUIRE_DESKTOP=1` 能把跳过变成失败；光标用例还要求这个会话正在显示指针，
  托管 runner 不显示，它在那里也打印跳过。另外 26 个在 Windows 11 与 CI 上都通过。
- 签过名的安装包还是安装包：证书表追加在捆绑数据之后（流水线签名时 Authenticode 就是这么写的），
  不再挡住运行时读取自己资源的那个尾标记。
- 构建器拒绝自己不读的配置键。以前能解析却什么也不做的设置，不会再被当成已经生效发出去；
  报错信息会点出这个键，以及该改用哪个设置。
- 运行中的任务可以停掉：`cancel` 按钮，或对关闭提问回答"是"，都会让任务在当前这一步走完的检查点放弃
  并撤回已经写下的内容，而不是在机器上留下一份装了一半的产品；工程脚本通过 `is_cancelled` 看到同一个
  请求。它以前恒为 `false`。
- `scripts/capture_setup_snapshots.ps1` 会构建示例安装包，把工程声明的每一页都拍下来：向导第一页中文、
  英文、俄文各一张，另加每档更高缩放各一张（默认 150% 与 200%），其余页面各一张；再逐张对照项目自己的布局检查——客户区尺寸、
  声明了圆角的页面切角是否切掉、布局里用绝对坐标摆下的图片和标签是否都画出了东西、整页颜色数，以及各页画面
  互不相同（第一页另有按钮和版本行跟不跟着语言变）。它在有桌面会话的机器上跑；每拍一页就把该页临时排到
  `wizard.pages[0]` 再构建，拍完按原字节写回，所以没解包过示例 payload 的克隆会用一个同格式的空归档来构建。
  图上是按版面画出来的样子，不是走完流程走到那一步。

## 签名

构建器不签名，也不该由它来签名。安装包与卸载程序由发布它们的流水线签，就像 NSIS 生成的安装包由使用
NSIS 的产品去签：NSIS 自己只提供 `!finalize` 与 `!uninstfinalize` 两个钩子，把生成好的文件交给一条命令，
它自己不签。`scripts/sign.ps1` 在这里做同一件事：用 `NANO_INSTALLER_CERT_THUMBPRINT` 指定的证书签名并校验，
构建过程不会调用它。

这个项目欠那条流水线的是「签完之后还能用」。Authenticode 会把证书表追加在构建产物所有内容之后，
捆绑数据的尾标记就不再是文件的结尾；运行时现在会在文件尾部搜索这个标记，而不是直接读最后几个字节。
`a_setup_with_a_signature_appended_still_installs` 把这条行为钉住，用 signtool 与本地签发的证书签过的安装包
在 Windows 11 上装得进去。

## 已知限制

- 运行时内嵌 Rhai 引擎，每个运行时体积从约 0.57-0.66 MB 增至约 1.8-1.9 MB。
- 提权后的安装包与卸载程序都以高完整性运行，
  只往 `%LOCALAPPDATA%` 写数据的产品应该关掉 `install.require_admin`。
- 多显示器下的缩放：安装包同时申请 `dpiAware`（Windows 7/8.1 读取）
  与 `dpiAwareness`（Windows 10 1607 起读取，取值 `PerMonitorV2, PerMonitor`）。
  把窗口拖到缩放比例不同的显示器上，界面会按新显示器重新排版，字号和图片保持清晰；
  Windows 7 上还是系统按主显示器来缩放。

- 依赖的下载走 Windows 自带的 WinHTTP；https 请求里显式打开 TLS 1.1/1.2。Windows 7 SP1
  上这一步还要机器自己的 schannel 支持 TLS 1.2（KB3140245 及后续更新），缺了这次下载会失败并说明原因，
  不会退回明文；http 地址不受影响。

签名和 Windows 7 验收做完之后，产品就可以照 `examples/TapTap` 的结构接进来。
