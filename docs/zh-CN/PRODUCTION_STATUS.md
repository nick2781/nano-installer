# 当前生产状态

**当前实现尚不能用于生产发布。** 安装动作会写文件和注册表，请只在一次性虚拟机里验证。

## 已验证

- 构建器与运行时是两个独立程序，安装包不含构建器。
- ZIP 与 7z payload 按文件头来识别，再选对应的运行时。
- 两个运行时都能正确解开真实归档，结果与预期 SHA-256 一致。
- 卸载程序使用自己的运行时和页面列表，不链接任何解包后端。
- CLI 与 Windows 10+ GUI 驱动同一套构建 API，GUI 依赖不会进入运行时。
- 安装包里带着 payload、项目资源，以及一个自包含的卸载程序，卸载程序有自己的图标和版本信息。
- 安装会解压 payload，把文件和卸载程序放进新目录，写入 manifest 与卸载项；
  卸载只删 manifest 里记录的内容。
- 目标目录里已经有同一个项目时，就地升级：删掉新版 payload 里不再包含的文件，
  任何一步出错都会恢复到升级前的版本。
- 首屏用原生方式渲染背景位图和 Unicode 文字，窗口没有边框、四角是圆的，可以拖动、最小化和关闭，
  鼠标移到可点击控件上会显示手型光标。
- 每个生成的文件都过了一遍 PE 导入审计，检查 Windows 7 SP1 x64 兼容性。
- 进度页实时汇报状态，完成页可以启动已经部署好的应用。
- 快捷方式和自启动项在安装时创建、卸载时还原，回滚路径也一样处理。
- 卸载会结束正在运行的产品、清掉快捷方式；只有用户取消勾选保留数据时，才会删掉声明过的用户数据。
- 内嵌的 Rhai 引擎负责执行 `scripts/install.rhai` 与 `scripts/uninstall.rhai`，
  脚本里用的原语直接复用内置的部署、回滚和 manifest 代码。脚本失败会回滚，
  脚本漏掉 manifest 清理时，库会补上。
- 流式布局覆盖嵌套 `VBox`、`HBox`、`Content`，支持内边距、外边距、百分比尺寸、
  `justify-content` 与 `align-items`。
- 文案里的 Markdown 链接点一下就打开配置好的网址，`close_confirm` 弹出的确认框带着项目自己的皮肤，
  目录选择框会把选中的路径写回布局里的 TextInput。
- 控件按布局声明的 `background`、`border-color` 与 `border-radius` 来绘制；语言菜单展开后上下键、
  回车与 Esc 都能用。
- 文本框可以直接编辑：点一下落下闪烁光标，输入就插入，Backspace 与 Delete 删除字符，方向键、Home、
  End 移动光标；按住左键拖动或双击可以选中文字并高亮，Ctrl+A 全选，Ctrl+C/X/V 复制、剪切和粘贴，
  Ctrl+Z/Y 撤销与重做，Ctrl+Backspace/Delete 和 Ctrl+左右键按词操作，连续输入合并成一步。
  声明 `readonly` 的字段保持只读展示。
- 流式布局拿 `flex-basis` 当起点来分配剩余空间；每个元素都可以设 `align-self`；
  嵌套容器按里面的内容参与外层测量；
  绝对定位的元素可以用 `right`/`bottom` 或 `inset` 简写从另一侧定位。
- 容器声明 `flex-wrap` 后，一行放不下就会折行；默认仍然是先压缩可收缩项。
- 安装包会写入应用程序清单：打开 `install.require_admin` 后，Windows 会在进程启动前弹出提权确认；
  `ui.dpi_aware` 告诉系统窗口要不要自己缩放。两个都不配置时，就按普通程序的方式运行。
- 构建器会把每个语言文件与默认语言、页面实际引用的键比一遍，报出缺文案的语言，
  以及 `supported_locales` 里列了却没有对应文件的语言。
- 卸载完成后，临时目录里的清理副本会立刻删掉卸载程序和已经清空的安装目录。
  目录里还有用户自己的文件时就保留目录，清理副本做完也会自动退出并消失。
- 项目声明 `advanced.silent_mode_support` 后，加上 `--silent` 就会静默安装；
  声明 `advanced.uninstall_mode_support` 后，同样可以静默卸载。静默运行不开任何界面，
  只接受 `--dir`，其它参数一律拒绝，结果靠退出码和标准错误返回。项目没有声明时，安装包会直接拒绝，
  不会悄悄装上或卸掉。
- `crates/nano-installer-core/tests/e2e_setup.rs` 里的安装包级用例会自己造项目、
  构建安装包并真的装上：文件逐字节写盘，manifest 与卸载项写入，升级时删掉旧文件、
  保留不属于它的文件，卸载时清掉产品、注册项和目录。14 个用例里有一个会开出向导窗口、
  量它画出来的客户区；开窗口要可交互的桌面会话，没有桌面的机器上这条跳过，
  `NANO_INSTALLER_E2E_REQUIRE_DESKTOP=1` 能把跳过变成失败。另外 13 个在 Windows 11 与 CI 上都通过。
- 签过名的安装包还是安装包：证书表追加在捆绑数据之后（流水线签名时 Authenticode 就是这么写的），
  不再挡住运行时读取自己资源的那个尾标记。
- `scripts/capture_setup_snapshots.ps1` 会构建示例安装包，把打开后的那一页拍下来：中文、英文、俄文各一张，
  另加一张 150% 缩放的；再逐张对照项目自己的布局检查——客户区尺寸、切掉的角、Logo 与标语是否画出了图案、
  按钮与版本行是否用布局声明的颜色画出了文字，以及按钮和版本行会不会跟着语言变。它在有桌面会话的机器上跑，
  而且只拍第一页，所以没解包过示例 payload 的克隆会用一个同格式的空归档来构建。

## 签名

构建器不签名，也不该由它来签名。安装包与卸载程序由发布它们的流水线签，就像 NSIS 生成的安装包由使用
NSIS 的产品去签：NSIS 自己只提供 `!finalize` 与 `!uninstfinalize` 两个钩子，把生成好的文件交给一条命令，
它自己不签。`scripts/sign.ps1` 在这里做同一件事：用 `NANO_INSTALLER_CERT_THUMBPRINT` 指定的证书签名并校验，
构建过程不会调用它。

这个项目欠那条流水线的是「签完之后还能用」。Authenticode 会把证书表追加在构建产物所有内容之后，
捆绑数据的尾标记就不再是文件的结尾；运行时现在会在文件尾部搜索这个标记，而不是直接读最后几个字节。
`a_setup_with_a_signature_appended_still_installs` 把这条行为钉住，用 signtool 与本地签发的证书签过的安装包
在 Windows 11 上装得进去。

## 已知限制

- 运行时内嵌 Rhai 引擎，每个运行时体积从约 0.57-0.66 MB 增至约 1.8-1.9 MB。
- 提权后的安装包与卸载程序都以高完整性运行，
  只往 `%LOCALAPPDATA%` 写数据的产品应该关掉 `install.require_admin`。
- 多显示器下的缩放：安装包同时申请 `dpiAware`（Windows 7/8.1 读取）
  与 `dpiAwareness`（Windows 10 1607 起读取，取值 `PerMonitorV2, PerMonitor`）。
  把窗口拖到缩放比例不同的显示器上，界面会按新显示器重新排版，字号和图片保持清晰；
  Windows 7 上还是系统按主显示器来缩放。

签名和 Windows 7 验收做完之后，产品就可以照 `examples/TapTap` 的结构接进来。
