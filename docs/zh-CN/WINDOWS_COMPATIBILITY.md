# Windows 兼容性

你发布出去的每个文件都针对 `x86_64-win7-windows-msvc` 构建，最低支持 Windows 7 SP1 x64。只有这一套
构建，没有 32 位或 ANSI 变体要跟着维护。

可视化构建器（`nano-installer-gui-x64.exe`）用的是 eframe/egui，所以需要 Windows 10 x64 及以上。
它只负责生成安装包，生成的安装包是面向 Windows 7 SP1 构建的。

**Windows 7 支持从来没有被观察过。** 上面的基线是每次构建的目标，也是导入审计检查的对象，所以安装包
调用的东西都不是 Windows 7 之后才有的。但这只是关于导入的论证，不是一次实测：没有任何安装包在
Windows 7 SP1 机器上跑过。请把它当成声明，发给 Win7 用户之前自己在那台机器上测一遍。
[怎么跑这次验收](#怎么跑这次验收) 就是把声明变成事实的做法，写成任何拿到机器的人都能照着走。

## 运行时依赖什么

- Win32 Unicode API：窗口、控件与文字
- WIC 解码 PNG，GDI 做透明混合绘制
- Windows 7 SP1 就已存在的注册表、shell 与进程 API：注册表键的 32/64 位视图用
  `KEY_WOW64_32KEY` 与 `KEY_WOW64_64KEY` 读，命令输出按 ANSI 代码页解开用 `MultiByteToWideChar`，
  两者都自 Windows XP 起就有
- 服务控制管理器：脚本装的那个服务就是机器自己的一条记录，装、改、停、删都走这里，
  本项目支持的系统都比 Windows 7 更早就带着它
- IMM32：管文本框的输入法组合窗与候选窗，Windows 7 自带
- WinHTTP 取回工程声明要下载的依赖，https 时打开 TLS 1.1/1.2（Windows 7 SP1 上还需要机器自己的
  schannel 支持 TLS 1.2，即 KB3140245 及后续更新；缺了就报错，不会退回明文）

正式构建使用固定的 `nightly-2025-11-08` 工具链、`rust-src`、
`-Z build-std=std,panic_abort`、静态链接 CRT 与 `panic=abort`。

## 兼容性如何检查

每次构建都会过一遍 PE 导入表，构建器、三个运行时和每个生成出来的安装包都在内：一旦出现被禁用的
Windows 8 或 Windows 10 API，构建就失败。这样能证明文件在静态导入层面不依赖更新的系统 API。

静态检查证明不了安装包真的能用，下面这些也还没有被观察过。要正式声明支持 Windows 7 SP1 x64，你还得在干净机器上把 PNG
解码、文字渲染、鼠标输入、窗口行为、解压、安装与卸载整套验证跑一遍。目标机器建议安装 KB3033929
更新（SHA-2 代码签名支持）。

## 怎么跑这次验收

要求写在上面，这一节是怎么满足它。目的是让这次运行留下可查的记录，而不是一段回忆。

**准备。** 一台干净的 Windows 7 SP1 x64 机器或虚拟机，内部版本 7601，装好 KB3033929；先做快照，
因为验收会往机器上装软件。工程若要下载依赖，机器还需 KB3140245 及之后的更新才支持 TLS 1.2，否则
这一步记为「未覆盖」。构建这一步不需要工具链：从发布里取构建器与那三个运行时
（见[快速开始](QUICK_START.md)），放进同一个目录，再让它对着工程跑：

```powershell
.\nano-installer-native-x64.exe build --project <你的工程>
```

再把生成的那一个 exe 拷到 Windows 7 机器上。验收用的工程最好页面齐全、语言不止一种、带 PNG 素材和
payload，并且有快捷方式与卸载流程；`examples/TapTap` 加一份你自己的 payload，就是这套文档一直在验证
的样子。

**逐项观察。** 下面每一条都对应本仓的一条声明：

1. 以普通用户身份运行。窗口应当无边框、四角圆角，背景位图与 logo 画得出来（PNG 解码、alpha 混合、
   GDI 绘制），文字是工程自己的语言，指针移到可点击的控件上变成手型。
2. 按住背景拖动窗口，最小化，再还原。
3. 工程有多种语言时切换一次，页面应当重画。
4. 把每一页走一遍，包括会报出当前步骤的进度页；完成页若配置了启动程序，也要点一下。
5. 装完看机器上留下了什么：文件、快捷方式（桌面、开始菜单、开机启动）、卸载入口，以及卸载程序
   之后要读的 manifest。
6. 工程若有 `scripts/install.rhai`，核对脚本做了什么。
7. 从卸载入口卸载：产品的文件与快捷方式应当消失，没勾选删除时用户数据保留，安装目录空了就删掉。
8. 开着读屏（讲述人或 NVDA），让它念出当前页面、焦点，以及正在输入的字段。
9. 工程若安装服务，确认服务存在、能启动，卸载后不再存在。

**记录结果。** 记下机器版本（`winver`：「版本 6.1（内部版本 7601: Service Pack 1）」）、安装包的版本或
tag、由哪个工程构建、是否提权运行，以及上面每一条的观察结果：发生了什么，或者哪一条没覆盖、为什么。
然后回到仓库：

- `docs/{en,zh-CN}/PRODUCTION_STATUS.md` 的「已验证」清单补上观察到的内容，并改掉文档开头「Windows 7
  从未被观察过」那句话；
- `CHANGELOG.md` 加一条 `已验证`，写明机器版本、覆盖的是哪个 release、以及没覆盖什么。

不必每个 release 都重跑。这次运行覆盖到的部分变了再跑，例如运行时、某一类页面、manifest、卸载程序或
某个 Win32 调用，并在记录里写明覆盖的是哪个 release。它也不可能代表所有 Windows 7 安装：32 位
Windows 7 与 ARM64 不在支持范围内，未装 SP1 的机器也不在声明范围内。
