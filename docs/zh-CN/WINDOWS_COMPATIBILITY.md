# Windows 兼容性

你发布出去的每个文件都针对 `x86_64-win7-windows-msvc` 构建，最低支持 Windows 7 SP1 x64。只有这一套
构建，没有 32 位或 ANSI 变体要跟着维护。

可视化构建器（`nano-installer-gui-x64.exe`）用的是 eframe/egui，所以需要 Windows 10 x64 及以上。
它只负责生成安装包，生成的安装包仍然能在 Windows 7 SP1 上运行。

## 运行时依赖什么

- Win32 Unicode API：窗口、控件与文字
- WIC 解码 PNG，GDI 做透明混合绘制
- Windows 7 SP1 就已存在的注册表、shell 与进程 API：注册表键的 32/64 位视图用
  `KEY_WOW64_32KEY` 与 `KEY_WOW64_64KEY` 读，命令输出按 ANSI 代码页解开用 `MultiByteToWideChar`，
  两者都自 Windows XP 起就有
- 服务控制管理器：脚本装的那个服务就是机器自己的一条记录，装、改、停、删都走这里，
  本项目支持的系统都比 Windows 7 更早就带着它
- IMM32：管文本框的输入法组合窗与候选窗，Windows 7 自带
- WinHTTP 取回工程声明要下载的依赖，https 时打开 TLS 1.1/1.2（Windows 7 SP1 上还需要机器自己的
  schannel 支持 TLS 1.2，即 KB3140245 及后续更新；缺了就报错，不会退回明文）

正式构建使用固定的 `nightly-2025-11-08` 工具链、`rust-src`、
`-Z build-std=std,panic_abort`、静态链接 CRT 与 `panic=abort`。

## 兼容性如何检查

每次构建都会过一遍 PE 导入表，构建器、三个运行时和每个生成出来的安装包都在内：一旦出现被禁用的
Windows 8 或 Windows 10 API，构建就失败。这样能证明文件在静态导入层面不依赖更新的系统 API。

静态检查证明不了安装包真的能用。要正式声明支持 Windows 7 SP1 x64，你还得在干净机器上把 PNG
解码、文字渲染、鼠标输入、窗口行为、解压、安装与卸载整套验证跑一遍。目标机器建议安装 KB3033929
更新（SHA-2 代码签名支持）。

## 怎么跑这次验收

上面那段是要求，这一节是怎么满足它——让这次运行留下证据，而不是留下一个印象。

**准备。** 一台干净的 Windows 7 SP1 x64 机器或虚拟机，build 7601，装好 KB3033929，并且先做个
检查点/快照，因为这次运行会往机器上装东西。如果工程声明了要下载的依赖，机器还需要 KB3140245
及之后的更新来支持 TLS 1.2，否则那一步记为「未覆盖」。安装包在有工具链的机器上构建——用发布出来的
构建器与 stub 就够：

```powershell
.\target\release\nano-installer-native-x64.exe build --project <你的工程> --stubs <stub 目录>
```

然后把生成的那一个 exe 拷到 Windows 7 机器上。用一个「有多个页面、有不止一种语言、有 PNG 素材、
有 payload、有快捷方式、能卸载」的工程来验，比用一个空工程有意义；`examples/TapTap` 配一份你自己的
payload，就是这套文档一直在验证的形状。

**按顺序观察。** 下面每一条都对应这个仓里的一条声明：

1. 以普通用户身份运行：窗口无边框、圆角，背景位图与 logo 画出来（PNG 解码、alpha 混合、GDI），
   文字是工程自己的语言，指针移到可点的东西上会变成手型。
2. 按住背景拖动窗口、最小化、还原。
3. 工程有多种语言时切换一次，看页面重画。
4. 把每一页都走一遍，包括会报出当前步骤的进度页；工程配置了的话，还包括点完成页启动刚装好的程序。
5. 装完之后看机器上留下了什么：文件、快捷方式（桌面、开始菜单、开机启动）、卸载入口，以及卸载器
   将来要读的那份 manifest。
6. 工程里有 `scripts/install.rhai` 的话，脚本做的事也要核。
7. 从卸载入口卸载：产品的文件与快捷方式都没了，用户数据在没勾选删除时保留，安装目录空了就被删掉。
8. 开着读屏（讲述人或 NVDA），让它念出当前页面、焦点，以及正在输入的字段。
9. 工程会安装服务的话，确认服务存在、能启动、卸载后不在了。

**记录。** 写下机器版本（`winver`：「版本 6.1（内部版本 7601: Service Pack 1）」）、安装包的版本或
tag、它由哪个工程构建、是否提权运行，以及上面每一条的观察结果——发生了什么，或者没覆盖到以及为什么。
然后回到仓库里：

- `docs/{en,zh-CN}/PRODUCTION_STATUS.md` 的「已验证」清单补上这次观察到的东西，文档开头那句
  「Windows 7 从未被观察过」也随之改掉；
- `CHANGELOG.md` 加一条 `已验证`，写明机器版本、这次运行覆盖的是哪个 release、以及没覆盖什么。

不必每个 release 都重跑一次。这次运行摸过的东西变了就重跑——运行时、某一类页面、manifest、卸载器、
某个 Win32 调用——并说明它覆盖的是哪个 release。它同样证明不了所有 Windows 7 安装：32 位 Windows 7
与 ARM64 根本不在支持范围内，而没有 SP1 的机器也不是这些产物声明的那条基线。
