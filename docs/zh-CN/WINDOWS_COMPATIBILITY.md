# Windows 兼容性

发布出去的每个文件都针对 `x86_64-win7-windows-msvc` 构建，最低支持的版本是 Windows 7 SP1 x64。只有这
一套目标，没有 32 位版本，也没有 ANSI 版本需要另外维护。

可视化构建器 `nano-installer-gui-x64.exe` 基于 eframe/egui，需要 Windows 10 x64 及以上。它只负责生成
安装包，生成出来的安装包仍按上面的最低版本构建。

最低支持的版本已经验收过一次：内部版本 7601 的 Windows 7 SP1 x64，一次性虚拟机，装的是当前构建器生成的
安装包。导入审计每次构建都会跑，证明这些文件不依赖更新的系统 API；那次实机运行说明它们确实能用。覆盖到
哪、没覆盖到哪，记在[当前生产状态](PRODUCTION_STATUS.md)；想自己再走一遍，见
[怎么跑这次验收](#怎么跑这次验收)。

## 运行时依赖什么

- Win32 Unicode API：窗口、控件和文字
- WIC 解码 PNG，GDI 负责透明混合
- Windows 7 SP1 时代就有的注册表、shell 和进程 API。注册表键的 32/64 位视图分别用
  `KEY_WOW64_32KEY` 和 `KEY_WOW64_64KEY` 读取；命令输出按 ANSI 代码页解开，交给
  `MultiByteToWideChar` 转换。这两个调用从 Windows XP 起就有
- 服务控制管理器：脚本装的服务就是机器上的一条普通服务记录，安装、修改、停止、删除都走这套接口。本项目
  支持的系统比 Windows 7 更早就带上了它
- IMM32：负责输入法的组合窗和候选窗，Windows 7 自带
- WinHTTP：按工程声明下载依赖。走 https 时启用 TLS 1.1/1.2；在 Windows 7 SP1 上还需要系统自身的
  schannel 支持 TLS 1.2，也就是 KB3140245 及后续更新。缺了就直接报错，不会退回明文

正式构建使用固定的 `nightly-2025-11-08` 工具链、`rust-src`、
`-Z build-std=std,panic_abort`、静态链接 CRT 与 `panic=abort`。

## 兼容性如何检查

每次构建都会检查 PE 导入表，范围包括构建器、三个运行时和每一个生成的安装包。一旦出现 Windows 8 或
Windows 10 才有的 API，构建就会失败，这证明这些文件在静态导入层面不依赖更新的系统。

静态检查证明不了安装包真的能用，所以还有一次实机验收，而它已经跑过了：在内部版本 7601 上，PNG 解码、
文字渲染、鼠标输入、窗口行为、解压、安装和卸载都走通了，逐条结果见
[当前生产状态](PRODUCTION_STATUS.md)。那次没走到的部分是窗口拖动、多显示器缩放、光标形状，以及服务的
安装与卸载；读屏只读到了无障碍树（内容与 Windows 11 逐字节一致），没有真的开着讲述人或 NVDA 听过。目标
机器建议装 KB3033929（SHA-2 代码签名支持）；工程要下载依赖时，还需要 KB3140245 及之后的更新。

## 怎么跑这次验收

目的是让这次运行留下可查的记录，而不是一段回忆。

**准备。** 找一台干净的 Windows 7 SP1 x64，内部版本 7601，装好 KB3033929。先做快照，因为验收会往机器上
装软件。工程要下载依赖时，这台机器还需要 KB3140245 及之后的更新，否则 TLS 1.2 用不了，这一条记为
「未覆盖」。构建不需要工具链：从发布里取构建器和那三个运行时（见[快速开始](QUICK_START.md)），放在同一个
目录里，对着工程跑：

```powershell
.\nano-installer-native-x64.exe build --project <你的工程>
```

然后把生成的那一个 exe 拷到 Windows 7 机器上。验收用的工程最好页面齐全、语言不止一种、带 PNG 素材和
payload，并且有快捷方式和卸载流程；`examples/TapTap` 加一份你自己的 payload，就是这套文档一直在验证的
样子。

**逐项观察。** 下面每一条都对应本仓库的一条声明：

1. 以普通用户身份运行。窗口应当无边框、四角圆角，背景位图和 logo 画得出来（PNG 解码、alpha 混合、GDI
   绘制），文字是工程自己的语言，鼠标移到可点击的控件上会变成手型。
2. 按住背景拖动窗口，最小化，再还原。
3. 工程有多种语言时切换一次，页面应当重画。
4. 把每一页走一遍，包括会报出当前步骤的进度页；完成页若配置了启动程序，也要点一下。
5. 装完检查机器上留下了什么：文件、快捷方式（桌面、开始菜单、开机启动）、卸载入口，以及卸载程序之后要读
   的 manifest。
6. 工程若有 `scripts/install.rhai`，核对脚本做了什么。
7. 从卸载入口卸载：产品的文件和快捷方式应当消失；没有勾选删除时用户数据保留；安装目录空了就删掉。
8. 开着读屏（讲述人或 NVDA），让它念出当前页面、焦点，以及正在输入的字段。
9. 工程若安装服务，确认服务存在、能启动，卸载后不再存在。

**记录结果。** 记下机器版本（`winver` 显示「版本 6.1（内部版本 7601: Service Pack 1）」）、安装包的版本
或 tag、由哪个工程构建、是否提权运行，以及上面每一条的结果：实际发生了什么，或者哪一条没覆盖、为什么。
然后回到仓库：

- 把观察到的内容补进 `docs/{en,zh-CN}/PRODUCTION_STATUS.md` 的「已验证」清单，并写明这次覆盖的是哪个
  release；
- 在 `CHANGELOG.md` 的标记之下加一条 `已验证`，写明机器版本、覆盖的是哪个 release，以及没覆盖什么。

不必每个 release 都重跑。运行时、某一类页面、manifest、卸载程序或某个 Win32 调用有变化时再跑，并在记录
里写明覆盖的是哪个 release。它也不代表所有 Windows 7 安装：32 位 Windows 7 和 ARM64 不在支持范围内，
没装 SP1 的机器也不在声明范围内。
