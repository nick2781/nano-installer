# 可视化构建

可视化构建是 CLI 所用同一套构建引擎的 Windows 10+ 前端，不会把 CLI 当作子进程启动。

```powershell
.\target\release\nano-installer-gui-x64.exe
```

启动后是一个空工作区，不会自动打开任何示例。

## 五步完成一次构建

1. **Open project** 选择包含 `installer_config.json` 的项目目录。
2. **Refresh** 重新读取 JSON、XML、资源和 payload，不会覆盖同一项目已自定义的输出路径。
3. **Parameters** 设置项目目录、输出 exe 和可选的运行时目录。**Reset output** 恢复
   `dist/<output.installer_name>`；**Use automatic stub search** 恢复自动查找。
4. **Build setup** 异步构建。构建会在 worker 线程中重新校验项目，结果不依赖界面当前显示的摘要。
5. **Save log...** 导出完整日志，**Open output** 在资源管理器中定位产物；**After build** 控制
   成功后是否自动定位。

构建失败时 **Retry** 会用完全相同的参数重试，方便修好文件或运行时后继续。

## 窗口里有什么

界面按传统构建工作台组织：顶部是标准菜单栏，左侧是项目摘要，主区域是构建日志或参数页，
底部是唯一的构建操作区和常驻状态栏。

左侧栏按用途分组显示配置校验、版本与安装包语言、打包输入（payload、匹配的运行时、安装与卸载
图标、卸载程序名）以及默认安装目录。长路径显示盘符和末端目录，悬停可看完整路径。「上次校验
通过」会带上检查时间，只反映当时的项目状态；磁盘文件变化后需要刷新。DPI 素材警告只比较 1x/2x
PNG 是否成对，不能当作完整的生产检查。

## 读懂日志

日志记录实际执行的步骤：安装与卸载运行时的解析路径和大小、卸载程序在 bundle 内的名称、各资源
目录的文件数量与大小、payload 格式以及 bundle 索引。资源直接写入自定义 bundle，不生成中间
`skins.zip`；payload 保持你提供的 ZIP 或 7z 格式。

卸载程序有独立的、不含 payload 的 UI bundle，因此 `layouts`、`assets`、`locales`、`scripts`
会先以 `Uninstaller bundle:` 前缀收集一次，再为主安装包收集一次；payload 只打包进主安装包。

日志行使用本地时间戳 `[YYYY-MM-DD HH:mm:ss.SSS]`。可选择的日志窗口中，警告为琥珀色、错误为红色，
支持鼠标拖选、滚轮、横向滚动、`Ctrl+A` 和 `Ctrl+C`；**Copy all** 无需选择即可复制完整日志。
保存和复制时保留原文与时间戳。

菜单保持固定最小宽度和单行文字，中英文切换不会改变菜单几何结构。菜单还提供 **Open config**
（用系统默认程序打开 `installer_config.json`）、清空日志和退出。构建期间按钮会禁用，避免同时
启动两个打包任务。

## 界面语言

**视图 > 界面语言** 提供 English 与简体中文。它只翻译构建工具自身的控件；你生成的安装包的语言
由项目自己的 `locales` 文件和 XML 决定。构建日志的工具文案始终为英文，Windows 或文件系统返回的
错误保留原文，便于定位路径与错误码。

## 它不做什么

构建工具只编辑本次构建的参数，不会改写你的 JSON 或 XML，项目配置始终是唯一事实来源。payload 的
压缩方式由文件头决定，因此刻意不提供不会生效的「压缩方式」下拉框。
