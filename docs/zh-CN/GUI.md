# 可视化构建

可视化构建器是 CLI 的前端，要在 Windows 10 及以上运行。它和 CLI 共用同一套构建引擎，所以不会把后者当子进程启动。
从[最新发布](https://github.com/nick2781/nano-installer/releases/latest)取
`nano-installer-gui-x64.exe` 和那三个运行时，放进同一个目录，然后启动它：

```powershell
.\nano-installer-gui-x64.exe
```

启动后是一个空工作区，不会自动打开示例；而从源码构建出来的可执行文件在 `target/release/` 下，那是贡献者走的路。

## 五步完成一次构建

1. **Open project** 选中放着 `installer_config.json` 的项目目录。
2. **Refresh** 重新读一遍 JSON、XML、资源和应用文件，但同一个项目里你改过的输出路径不会被覆盖。
3. **Parameters** 设置项目目录、输出 exe 和可选的运行时目录，这次构建要不要顺手交出一个企业分发的包，也在这里定：要的话就填那份包住安装包的 `.msi`。
   **Reset output** 把输出路径恢复成 `dist/<output.installer_name>`，**Use automatic stub search** 恢复自动查找。
   包路径默认跟着输出 exe 的名字走，你敲过之后就不再跟，而下面那行等价命令行会显示这次构建拿到的 `--msi`。
4. **Build setup** 异步构建，它在 worker 线程里重新校验项目，所以界面上的摘要影响不了结果。
5. **Save log...** 导出完整日志，**Open output** 在资源管理器里定位生成的安装包，**After build** 则控制构建成功后要不要自动定位。

构建失败时，**Retry** 会用完全相同的参数再试一次，你修好文件或运行时后就能接着跑。

## 窗口里有什么

界面按传统构建工作台来组织。顶部是标准菜单栏，左边是项目摘要；主区域显示构建日志或参数页，底部只有一块构建操作区和一个常驻状态栏。

左边栏里按用途分组：配置校验，版本和安装包语言，打包输入，安装配置。其中打包输入涵盖应用文件、匹配的运行时、安装与卸载图标和卸载程序名，而安装配置里放的是安装包要不要申请管理员权限和默认安装目录。

路径太长时只显示盘符和末尾目录，鼠标悬停才看得到完整路径。「上次校验通过」会带上检查时间，但它只说明当时的项目状态，所以磁盘上的文件一变，就得刷新。

**构建警告**会列出上次检查发现的问题：少了配对的 1x/2x PNG，某个语言缺了默认语言里已有的文案，`supported_locales` 里写了却没有对应文件的语言。这只是素材和译文之间的快速自检，代替不了发布检查清单。

## 读懂日志

日志列出你的构建实际执行的步骤：安装和卸载运行时解析到的路径和大小、卸载程序在 bundle 里的名字、各资源目录的文件数量和大小、应用文件的格式。最后是 bundle 索引，索引里每个条目都带着自己的 SHA-256。资源直接写进自定义 bundle，所以不生成中间的 `skins.zip`；应用文件也保持你提供的 ZIP 或 7z 格式。

卸载程序有独立的 UI bundle，里面不含应用文件，所以日志会先带上 `Uninstaller bundle:` 前缀，收集一遍 `layouts`、`assets`、`locales`、`scripts`，然后为主安装包再收集一遍。应用文件只打进主安装包。

工程在 `finalize.uninstaller` 或 `finalize.installer` 里写了自己的命令时，日志里还有它那一段：先是 `Running finalize.uninstaller: …`，说明这次对哪个文件跑哪条命令，接着是命令自己写下的每一行。命令失败时会给出退出码，那份安装包也不会留下。

日志行用本地时间戳 `[YYYY-MM-DD HH:mm:ss.SSS]`；日志窗口里的文字都能选中，鼠标拖选、滚轮、横向滚动、`Ctrl+A` 和 `Ctrl+C` 都能用，其中警告是琥珀色、错误是红色。**Copy all** 不用先选中就能复制完整日志，而保存和复制时都保留原文和时间戳。

菜单始终有固定的最小宽度，标签也只有一行，所以中英文切换不会让菜单移动。**Open config** 用系统默认程序打开 `installer_config.json`，菜单里还有清空日志和退出；而构建期间按钮会禁用，免得同时启两个打包任务。

## 界面语言

**视图 > 界面语言** 里有 English 和简体中文，但它只翻译构建工具自己的控件；你生成出来的安装包用什么语言，取决于项目里的 `locales` 文件和 XML。

构建日志里的工具文案一直是英文，而 Windows 或文件系统返回的错误也保留原文，方便你查路径和错误码。

## 它不做什么

构建工具只改本次构建的参数，不会动你的 JSON 或 XML，项目配置始终是唯一的事实来源。应用文件用什么压缩方式由文件头决定，所以这里干脆不做那个不生效的「压缩方式」下拉框。
