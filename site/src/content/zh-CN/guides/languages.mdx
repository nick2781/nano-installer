一种语言对应 `locales` 目录下的一个 UTF-8 JSON 文件。文件名就是它的语言代码：`en-US.json`、
`ja.json`、`zh-CN.json` 等。

```json
{
  "install_button": "立即安装",
  "version_info": "版本号 1.11.3.10000"
}
```

XML 布局里用 `@` 引用键：

```xml
<Button text="@install_button" ... />
<Label text="@version_info" ... />
```

启动时运行时读 `<locales_dir>/<default_locale>.json`。`default_locale` 来自配置，默认是 `zh-CN`。
文字用 Unicode API 画出来，所以没有 ANSI 代码路径，运行时本身也没有 ANSI 版本。

## 提供多种语言

在页面上放一个语言选择控件，每一项对应一个语言代码：

```xml
<Select action="switch_language" ...>
  <Option value="zh-CN" text="简体中文" />
  <Option value="en-US" text="English" />
</Select>
```

选中一项，运行时立刻重新加载对应的语言文件，并照着它把页面文字重画一遍。

<Aside type="caution" title="value 就是文件名">

每个 `Option` 的 `value` 都必须对应 `locales` 目录里一个 JSON 文件的文件名。

</Aside>

## 不点击也能验证某种语言

自动截图和快速检查可以先选定语言：

```powershell
$env:NANO_INSTALLER_TEST_LOCALE = "en-US"
.\examples\TapTap\dist\TapTap_Setup.exe
```

## 构建会替你检查什么

每次构建都会拿语言文件去比默认语言，也去比页面实际引用的键；缺口会写进构建器的告警列表：

- 某个语言缺少默认语言里已有的文案，告警会列出具体的键名。
- `localization.supported_locales` 里写了某种语言，却没有对应的 JSON 文件。

构建只报告默认语言里有的键，所以页面可以故意引用某个语言没翻的键。运行时遇到缺失的键，仍然回退到
默认语言，只翻了一半的安装包也能正常跑完。
