可视化构建器让你在 Windows 10 及以上不敲命令行就能构建安装包。它是 CLI 的前端，与 CLI 共用同一套
构建引擎，所以不会把后者当子进程启动。从[最新发布](https://github.com/nick2781/nano-installer/releases/latest)
取 `nano-installer-gui-x64.exe` 和那三个运行时，放进同一个目录，然后启动它：

```powershell
.\nano-installer-gui-x64.exe
```

启动后是一个空工作区，不会自动打开示例。如果从源码构建，同一个可执行文件会生成在 `target/release/`
下，那是贡献者走的路。

## 五步完成一次构建

<Steps>

1. **Open project** 选中放着 `installer_config.json` 的项目目录。
2. **Refresh** 重新读一遍 JSON、XML、资源和应用文件，但你在同一个项目里改过的输出路径不会被覆盖。
3. **Parameters** 设置项目目录、输出 exe 和可选的运行时目录。这次构建要不要另外产出一个企业分发的
   包，也在这里定：要的话就填那份包住安装包的 `.msi`。**Reset output** 把输出路径恢复成
   `dist/<output.installer_name>`，**Use automatic stub search** 恢复自动查找。包路径默认跟着输出
   exe 的名字走，你敲过之后就按你写的来，而下面那行预览会显示这次构建拿到的 `--msi`。
4. **Build setup** 异步构建，它在 worker 线程里重新校验项目，所以界面上的摘要影响不了结果。
5. **Save log...** 导出完整日志，**Open output** 在资源管理器里定位生成的安装包。**After build**
   则决定构建成功后要不要自动定位。

</Steps>

<Aside type="note" title="Retry 用的还是同一套参数">

构建失败时，先修好它指出的文件或运行时，再点 **Retry**。

</Aside>

## 窗口里有什么

界面按传统构建工作台来组织。顶部是标准菜单栏，左边是项目摘要；主区域显示构建日志或参数页，底部是
构建操作区和一个常驻状态栏。

左边栏按用途给设置分组：配置校验、版本和安装包语言、打包输入、安装配置。其中打包输入涵盖应用文件、
匹配的运行时、安装与卸载图标和卸载程序名。安装配置里放的是安装包要不要申请管理员权限、默认装到
哪个目录。

路径太长时只显示盘符和最后一段，鼠标悬停才能看到完整路径。

**构建警告**列出上次检查发现的问题：少了配对的 1x/2x PNG，某个语言缺了默认语言里已有的文案，
`supported_locales` 里写了却没有对应文件的语言。

<Aside type="caution" title="自检只说明那一刻">

「上次校验通过」带着检查时间，它只说明那一刻的项目状态，所以磁盘上的文件一变就要刷新。构建警告只是
素材的快速自检，代替不了发布检查清单。

</Aside>

## 读懂日志

日志列出这次构建实际执行的步骤：安装和卸载运行时解析到的路径和大小、卸载程序在 bundle 里的名字、
各资源目录的文件数量和大小、应用文件的格式。接着是 bundle 索引，每个条目旁边都有一个 SHA-256。
资源直接写进自定义 bundle，所以不生成中间的 `skins.zip`；应用文件也保持你给的 ZIP 或 7z 格式。

卸载程序有独立的 UI bundle，里面不含应用文件。所以日志会先把 `layouts`、`assets`、`locales`、`scripts`
收一遍，这些行都带 `Uninstaller bundle:` 前缀，然后再为主安装包收一遍。应用文件只进主安装包一次。

工程在 `finalize.uninstaller` 或 `finalize.installer` 里写了自己的命令时，日志里也有这一段。先是
一行 `Running finalize.uninstaller: …`，说明哪个文件交给哪条命令，接着是命令自己输出的每一行。命令
失败时，日志会给出退出码，也不会留下安装包。

日志行用本地时间戳 `[YYYY-MM-DD HH:mm:ss.SSS]`，日志窗口里的文字都能选中：鼠标拖选、滚轮、横向
滚动、`Ctrl+A`、`Ctrl+C` 都能用。警告是琥珀色，错误是红色。**Copy all** 不用先选中就能复制整份
日志，保存或复制出来的文字保留原文和时间戳。

菜单始终有固定的最小宽度，标签也只有一行，所以中英文切换不会让菜单移动。**Open config** 用系统
默认程序打开 `installer_config.json`，菜单里还有清空日志和退出。构建期间按钮会禁用，免得同时开
两个打包任务。

## 界面语言

**视图 > 界面语言** 里有 English 和简体中文，但它只翻译构建工具自己的控件。你生成出来的安装包用
什么语言，取决于项目里的 `locales` 文件和 XML。

界面的语言换成哪种，构建日志里的文案都还是英文；Windows 或文件系统返回的错误也保留原文，方便你
查路径和错误码。

## 它不做什么

构建工具只改本次构建的参数，从不动你的 JSON 或 XML，所以项目配置始终是唯一的事实来源。应用文件用
什么压缩方式由文件头决定，所以这里干脆不做那个不生效的「压缩方式」下拉框。
