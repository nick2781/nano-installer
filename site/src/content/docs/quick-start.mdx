This guide builds a per-user installer for an application named `MyApp.exe`. You need a Windows x64
machine and the application files you want to distribute. The downloaded builder needs no Rust toolchain.
Replace the product name and executable with your own after the first build works.

<Steps>

1. ## Download the tools

   Download these files from the **same [release](https://github.com/nick2781/nano-installer/releases/latest)**
   and keep them together:

   | File | Purpose |
   | --- | --- |
   | `nano-installer-native-x64.exe` | Command-line builder |
   | `lzma-stub-native.exe` | Runtime for 7z payloads |
   | `zlib-stub-native.exe` | Runtime for ZIP payloads |
   | `uninst-stub-native.exe` | Embedded uninstaller runtime |
   | `SHA256SUMS.txt` | Expected SHA-256 digests |

   Run `certutil -hashfile nano-installer-native-x64.exe SHA256` and compare the result with the
   corresponding line in `SHA256SUMS.txt`; repeat for the stubs.

   <Aside type="note" title="Keep one release together">
   The builder and all three stubs must come from the same release. The GUI is optional and requires
   Windows 10 or later. Repository releases are unsigned; see [distribution](/guides/distribution/).
   </Aside>

1. ## Prepare the project

   Create this structure, including the empty `assets` directory. Put `MyApp.exe` and its dependencies
   under `app/`.

   ```text
   my-project/
     installer_config.json
     app/
       MyApp.exe
     assets/
     layouts/
       install.xml
       uninstall.xml
     locales/
       en-US.json
     payload/
       app.zip
   ```

   From `my-project/`, create the payload:

   ```powershell
   Compress-Archive -Path .\app\* -DestinationPath .\payload\app.zip -Force
   ```

   <Aside type="caution" title="Check the archive root">
   `MyApp.exe` must be at the archive root rather than inside an extra `app` folder. The configured
   `install.exe_name` must match its path in the archive, or the installed application cannot be launched.
   </Aside>

   Write the following files as UTF-8. This project uses the built-in deployment steps, so it needs no
   Rhai script or plugin. The [configuration reference](/reference/configuration/) covers additional settings.

   ### Product configuration

   ```json title="installer_config.json"
   {
     "project": { "name": "MyApp", "version": "1.0.0", "publisher": "Example Company" },
     "output": { "installer_name": "MyApp_Setup.exe" },
     "resources": { "payload_file": "payload/app.zip" },
     "localization": { "default_locale": "en-US", "supported_locales": ["en-US"] },
     "install": {
       "default_path": "%LOCALAPPDATA%\\MyApp",
       "exe_name": "MyApp.exe",
       "require_admin": false
     },
     "registry": { "uninstall_key": "HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Uninstall\\MyApp" },
     "wizard": {
       "pages": [{ "id": "install", "layout": "layouts/install.xml" }],
       "uninstall_pages": [{ "id": "uninstall", "layout": "layouts/uninstall.xml" }]
     },
     "advanced": { "silent_mode_support": true, "uninstall_mode_support": true }
   }
   ```

   ### Pages

   ```xml title="layouts/install.xml"
   <Page width="480" height="240" background="#FFFFFFFF">
     <Label text="MyApp" left="32" top="28" width="416" height="32" font-size="22" color="#FF202020" />
     <Button text="@install" action="install" left="32" top="120" width="200" height="40" color="#FF202020" />
     <Button text="@close" action="close" left="248" top="120" width="200" height="40" color="#FF202020" />
   </Page>
   ```

   ```xml title="layouts/uninstall.xml"
   <Page width="480" height="240" background="#FFFFFFFF">
     <Label text="MyApp" left="32" top="28" width="416" height="32" font-size="22" color="#FF202020" />
     <Button text="@uninstall" action="uninstall" left="32" top="120" width="200" height="40" color="#FF202020" />
     <Button text="@close" action="close" left="248" top="120" width="200" height="40" color="#FF202020" />
   </Page>
   ```

   ### UI text

   ```json title="locales/en-US.json"
   { "install": "Install", "uninstall": "Uninstall", "close": "Close" }
   ```

   This single-page project reports completion in a message box. A full wizard normally adds separate
   progress and finish pages; see [page layout](/guides/page-layout/).

1. ## Build the installer

   From the directory containing the downloaded tools, run:

   ```powershell
   .\nano-installer-native-x64.exe build --project C:\path\to\my-project
   ```

   The result is `my-project/dist/MyApp_Setup.exe`. The builder selects the ZIP runtime from the
   archive signature and embeds the uninstaller. If the stubs live elsewhere, add `--stubs C:\path\to\stubs`.
   All build options are in the [command-line reference](/reference/cli/).

1. ## Test installation and removal

   Copy the setup to a clean VM before running it. This configuration installs under the current user's
   `%LOCALAPPDATA%` without asking for elevation.

   1. Run the setup and choose **Install**. Check that `MyApp.exe` and `uninst.exe` appear in the target directory.
   2. Launch `MyApp.exe` and verify that its dependencies are present.
   3. Find MyApp in Windows Programs and Features, then uninstall it. Check that recorded application files are removed.
   4. Reinstall, then build version `1.0.1` with a changed payload and install it over `1.0.0` to verify the upgrade.
   5. Exercise silent install and uninstall using the commands in [distribution](/guides/distribution/).

   For your production project, add your icon, product metadata and branding, and complete the
   [release checklist](/guides/distribution/). Errors and log locations are in [troubleshooting](/guides/troubleshooting/).

</Steps>

## Use the TapTap example

`examples/TapTap` demonstrates a complete branded wizard.

<Aside type="note" title="Prepare the example resources">
Clone with Git LFS: a source ZIP contains pointers instead of the images and compression tools. The repository does not include
`examples/TapTap/payload/app.7z`, so provide that archive yourself before building the example.
Its branding is not MIT-licensed and must not be reused for your product.
</Aside>
